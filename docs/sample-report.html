Kafka data/events: min.insync.replicas (3) leaves no room for a broker failure (replication factor 3)critical
Kafka/data/events

Producers using acks=all fail as soon as one replica is unavailable (rolling restarts included). Use min.insync.replicas = replication factor - 1 (typically RF 3, ISR 2). Right now only 2 brokers are ready, so writes are already failing with NotEnoughReplicas.

Fix available as a GitOps change: Set min.insync.replicas to 2 in the Kafka resource

ingress-nginx ingress-nginx/ingress-nginx: controller 1.11.3 is vulnerable to IngressNightmare (CVE-2025-1974)critical
Deployment/ingress-nginx/ingress-nginx-controller

CVE-2025-1974 (CVSS 9.8) lets anything that can reach the admission webhook run code in the controller, which can read every Secret in the cluster. Fixed in v1.11.5 and v1.12.1. Until upgraded, restrict access to the admission webhook with a NetworkPolicy.

image · registry.k8s.io/ingress-nginx/controller:v1.11.3@sha256:d56f135b6462cfc476447cfe564b83a45e8bb7da2774963b00d12161112270b7
Fix available as a GitOps change: Upgrade the controller image to v1.11.5 or later
Kong kong/kong: Admin API / Kong Manager is reachable from outside the clustercritical
Deployment/kong/kong-gateway

The Kong Admin API can create routes, plugins and consumers: whoever reaches it controls all traffic through the gateway (and can read credentials of consumers). Keep it ClusterIP and reach it with port-forward or behind authentication.
