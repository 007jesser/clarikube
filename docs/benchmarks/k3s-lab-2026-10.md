# Real-cluster results: k3s lab, October 2026

Single-node k3s v1.36.5 (Ubuntu 26.04 VM, 11 GB RAM) with the kubepilot lab: shop apps broken by a bad
release (`make lab-break`), a data tier with deliberate misconfigurations (`make lab-data`), Falco and
Trivy Operator. Numbers from `make lab-report` (see `lab/report.py`); the MCP session used Claude Code.

## What it found

| Workload | kubepilot's root cause | Correct? |
|---|---|---|
| shop/frontend | Revision 2 changed the image to `nginx:1.27.99-typo` (registry: NotFound) → revert | yes |
| shop/checkout | Revision 2 lowered the memory limit 512Mi → 128Mi (OOMKilled) → restore | yes |
| shop/worker | Requests 64Gi, node has ~11.5Gi allocatable: can never schedule | yes |
| shop/api | Secret `api-db-credentials` does not exist | yes |
| shop/reports | **Not a bug in reports: its dependency OpenSearch data/search is down** (logs: ECONNREFUSED) | yes |

Data tier, flagged without being asked: Redis exposed on a NodePort with no password, OpenSearch heap = memory
limit and security plugin disabled, RabbitMQ with 2 voting members, no PDB, management UI exposed, all three
on ephemeral storage.

## Speed and context

| | |
|---|---|
| Full cluster health | 0.37 s (0.01 s on follow-up calls, cached snapshot) |
| Per-workload diagnosis | ≤ 0.15 s |
| Whole investigation in Claude Code | 33 s, 10 tool calls |
| Context sent to the model | **~9.8k tokens** for everything above |
| Raw kubectl equivalent | ~67k tokens (`get pods -A -o yaml`, events, controllers, describe + logs of failing pods) — **6.8x more**, and uncorrelated |

Token counts are approximate (characters / 4). Raw output grows with every pod; kubepilot's output grows with
the number of problems, so the gap widens on real clusters. To be re-measured on larger clusters.

## Bugs the real cluster exposed (fixed, now regression tests)

The synthetic demo passed; the real cluster found four bugs in the first run:

1. A crash loop between back-offs shows as `Error` (terminated, exit 1), not `CrashLoopBackOff` → missed.
2. Readiness failures during container startup after a VM reboot (30 min earlier) → false "probe failing".
3. k3s ships `rancher/mirrored-coredns-coredns`, `rancher/mirrored-metrics-server` → not recognised.
4. `kubepilot capture` wrote the server version as a list of characters.

The capture is in `tests/fixtures/k3s-lab-2026-10` with tests in `tests/test_real_k3s.py`.
